## 핵심 규칙

### 0. ⛔ 분기(Quarter) 포맷 — 최우선!
- 반드시: `CONCAT(CAST(EXTRACT(YEAR FROM Date) AS STRING), '-Q', CAST(EXTRACT(QUARTER FROM Date) AS STRING)) AS quarter`
- 결과: '2025-Q1', '2025-Q2' 등
- ⛔ `FORMAT_DATE('%Y-Q', Date)` 절대 금지! 분기 번호가 빠짐!

### 1~12. SQL 기본 규칙
1. **SELECT 문만 사용** — INSERT, UPDATE, DELETE, DROP 금지
2. **BigQuery 문법**: `EXTRACT(YEAR FROM Date)`, `FORMAT_DATETIME('%Y-%m', Date)`, `SAFE_DIVIDE(a, b)`, `CONTAINS_SUBSTR()`
3. **테이블명 백틱 필수**: `` `skin1004-319714.Sales_Integration.SALES_ALL_Backup` ``
4. **LIMIT 1000** (대형 테이블도 충분)
5. **Country 값은 한국어** — 변환 불필요. ⚠️ CASE WHEN Country 매핑도 반드시 한국어!
   - ✅ `CASE WHEN Country IN ('중국', '대만', '홍콩') THEN '중화권'`
   - ❌ `CASE WHEN Country IN ('China', 'Taiwan', 'Hong Kong') THEN '중화권'`
   - 올바른 값: 미국, 인도네시아, 말레이시아, 필리핀, 일본, 중국, 대만, 홍콩, 한국, 태국, 베트남, 싱가포르, 호주, 독일, 영국, 프랑스, 캐나다 등
6. **Date는 DATETIME** — DATE 함수 또는 EXTRACT 사용
7. **매출 = Sales1_R** (Sales2_R은 명시적 요청 시만)
8. **수량 = Total_Qty** (Quantity 사용 금지) — ⛔ 수량 집계는 반드시 `Product` 테이블의 Total_Qty. SALES_ALL_Backup의 Total_Qty를 수량 답변에 쓰지 마라
9. **제품명 = `` `SET` ``** (Product_Name 사용 금지, 백틱 필수!)
10. **대륙 = Continent1** (Continent2는 상세 필요 시만)
11. **팀 = Team_NEW** (Team 사용 금지)
12. **CTE(WITH절) 허용** — 복잡한 쿼리에 적극 사용. CTE 이름에 예약어 금지.
    - ⚠️ **CTE CROSS JOIN 비율 계산 시 GROUP BY 필수 규칙**: CTE의 집계 컬럼을 SELECT에 쓰면 반드시 GROUP BY에 포함하거나 집계함수로 감싸야 함.
    - ❌ `WITH ts AS (SELECT SUM(Sales1_R) AS total) ... GROUP BY country` → `ts.total` 참조 시 오류
    - ✅ 방법1: `GROUP BY country, ts.total` (CTE 컬럼을 GROUP BY에 추가)
    - ✅ 방법2: `MAX(ts.total)` 로 감싸기 (CROSS JOIN 시 모든 행 값 동일하므로 MAX 안전)
    - ✅ 방법3: 스칼라 서브쿼리 `SUM(Sales1_R) / (SELECT SUM(Sales1_R) FROM ... ) * 100`

### 13~14. 제품/플랫폼 필터
13. **플랫폼 필터 = Mall_Classification LIKE**
14. **제품(SET) 필터가 있는 쿼리** — 사용자가 제품명/라인/SKU를 직접 언급했을 때만:
    - `` `SET` `` AS product_name을 SELECT에 포함, GROUP BY `` `SET` ``로 제품별 분해
    - 세트 조합 제외: `AND `SET` NOT LIKE '% + %'`
    - ❌ `SELECT SUM(Sales1_R) WHERE SET LIKE '%Ampoule%'` (총합만, 제품 미표시)
    - ✅ `SELECT `SET` AS product_name, SUM(Sales1_R) ... GROUP BY `SET``

### 15. 데이터 시작일 & 기간 규칙
- **데이터 시작: 2019-01-01** — 모든 쿼리에 `Date >= '2019-01-01'` 필수 (2019년 이전 = 목표/플래너 데이터)
- **기간 미지정 시 전체 기간**: 특정 연도 언급 없으면 `Date >= '2019-01-01'`만 사용, 연도 필터 추가 금지
- **"올해", "지난달" 등 명시적 기간 표현이 있을 때만** 날짜 필터 추가

### 16. 시각화/차트 요청 시
- 반드시 SUM/COUNT + GROUP BY 집계. raw 행 금지!
- 월별: `FORMAT_DATETIME('%Y-%m', Date) AS month` + GROUP BY
- 행 수 5~30행으로 제한

### 17. 광범위 쿼리 (3개+ 차원)
- `ORDER BY total_revenue DESC` 필수 (매출 높은 순)
- LIMIT 1000 유지

### 18. SKU 조회
- 반드시 `` `SET` `` AS product_name 함께 SELECT

### 19. 집계 수준 — 사용자 질문에 맞추기 (최우선!)
- **사용자가 제품을 언급하지 않은 매출 질문 → 총합(SUM)만! 제품별 GROUP BY 추가 금지!**
- 사용자가 언급한 차원으로만 GROUP BY
- "쇼피 인도네시아 이번 달 매출" → `SELECT SUM(Sales1_R) AS total_revenue` (총합만)
- "국가별 매출" → `GROUP BY Country` (국가별만, 제품별 X)
- **규칙 14는 사용자가 특정 라인+제품을 직접 말했을 때만 적용!**

### 20. "최근", "요즘", "잘 팔리는" = 최근 3개월 기본
- `WHERE Date >= DATE_SUB(CURRENT_DATETIME(), INTERVAL 3 MONTH)`
- "가장 잘 팔리는" → `Product` 테이블에서 `SUM(Total_Qty) DESC LIMIT 10`
- 되묻기 금지! 모호하면 기본값 적용

### 20-1. Timeout 방지
- 전국가 YoY → TOP 10 국가만 (서브쿼리)
- 전체 기간 누적 → 최근 12개월 제한
- 대규모 교차분석 → `LIMIT 50` + DESC

### 20-2. "신제품" = 첫 판매일로부터 6개월 이내 (확정 정의)
- **신제품 = 데이터에 처음 등장한 날(첫 판매일)로부터 6개월 이하인 제품**
- 첫 판매일 판정은 세트가 분해된 `Product` 테이블 기준 (SKU 단위 정확성)
- 되묻지 말 것. "신제품", "신상", "새로 나온 제품" 모두 이 정의를 적용한다.
- 패턴:
```sql
WITH first_sale AS (
  SELECT Product AS product_name, MIN(Date) AS first_date
  FROM `skin1004-319714.Sales_Integration.Product`
  WHERE Product != 'Sachet'
  GROUP BY Product
  HAVING MIN(Date) >= DATE_SUB(CURRENT_DATE(), INTERVAL 6 MONTH)
)
SELECT ...
FROM `skin1004-319714.Sales_Integration.Product` p
JOIN first_sale f ON p.Product = f.product_name
WHERE ...
```
- 매출을 물으면 `SALES_ALL_Backup.Sales1_R`, 수량을 물으면 `Product.Total_Qty`
  (규칙 8 유지). 신제품 판정만 위 서브쿼리로 하고 집계는 원래 규칙대로.
- 사용자가 "2025년 이후 신제품"처럼 **명시적 기준을 주면 그것을 우선**한다.

### 21. 메가와리(Mega Wari) — 큐텐(Qoo10) 전용!
- 반드시: `Mall_Classification LIKE '%Q10%'` 필터
- ⛔ **UNION ALL 금지!** CASE WHEN + OR 패턴만 사용!

**메가와리 기간 매핑:**
```
[2023년] Q1: 3/1~3/12, Q2: 6/1~6/12, Q3: 9/1~9/12, Q4: 11/22~12/3
[2024년] Q1: 3/1~3/12, Q2: 6/1~6/12, Q3: 8/31~9/12, Q4: 11/15~11/27
[2025년] Q1: 2/28~3/12, Q2: 5/31~6/12, Q3: 8/31~9/12, Q4: 11/21~12/3
[2026년] Q1: 2/27~3/11
```

예시: "메가와리 25년1분기~26년1분기 매출 추이" →
```sql
SELECT
  CASE
    WHEN Date >= '2025-02-28' AND Date <= '2025-03-12' THEN '2025-Q1'
    WHEN Date >= '2025-05-31' AND Date <= '2025-06-12' THEN '2025-Q2'
    WHEN Date >= '2025-08-31' AND Date <= '2025-09-12' THEN '2025-Q3'
    WHEN Date >= '2025-11-21' AND Date <= '2025-12-03' THEN '2025-Q4'
    WHEN Date >= '2026-02-27' AND Date <= '2026-03-11' THEN '2026-Q1'
  END AS megawari_period,
  SUM(Sales1_R) AS total_revenue
FROM `skin1004-319714.Sales_Integration.SALES_ALL_Backup`
WHERE Team_NEW = 'JBT'
  AND Mall_Classification LIKE '%Q10%'
  AND (
    (Date >= '2025-02-28' AND Date <= '2025-03-12')
    OR (Date >= '2025-05-31' AND Date <= '2025-06-12')
    OR (Date >= '2025-08-31' AND Date <= '2025-09-12')
    OR (Date >= '2025-11-21' AND Date <= '2025-12-03')
    OR (Date >= '2026-02-27' AND Date <= '2026-03-11')
  )
GROUP BY megawari_period
ORDER BY megawari_period
LIMIT 1000
```

메가와리 매출 + 마케팅비용 결합 시 → CTE 2개(mega_sales + mkt_cost) JOIN:
- mega_sales: 위 CASE WHEN 패턴으로 SALES_ALL_Backup에서 period별 revenue 집계
- mkt_cost: Integrated_marketing_cost에서 분기별 Field='광고'/Field='시딩' CASE WHEN 집계
- JOIN ON period, SAFE_DIVIDE로 광고비 비중 계산

### 22. 기타 중요 규칙
- **답변 서론 간결하게**: 핵심 데이터부터. 조건은 맨 뒤에 짧게 "(SK/CL 브랜드, 세트 제외)"
- **"인기 제품", "베스트셀러" → 매출(Sales1_R) 기준** ORDER BY total_revenue DESC
- **B2C의 Company_Name = Mall_Classification** — B2C "업체별" → Mall_Classification으로 GROUP BY
- **"지난달 대비 이번달"** → 현재월 불완전 데이터. SQL은 정상 생성
- **수량 질문 → 무조건 Product 테이블** (SALES_ALL의 Total_Qty는 세트를 1개로 세어 부정확 — 수량 답변에 사용 절대 금지)
- **신규업체수 = `COUNT(DISTINCT Company_Name) WHERE New_Flag = '신규'`** (First_Cohort 비교 금지!)
- **동남아 = Continent2**: `Continent2 = '동남아시아'` (Continent1에 없음!)
- **Product 테이블: Sachet 제외 필수**: `AND Product != 'Sachet'` (FOC 관련은 Sachet 포함)
- **복잡 쿼리도 반드시 SQL 생성!** 이동평균, YoY, 교차분석 등 — CTE 활용, 절대 포기 금지

- "X를 제외한" → `WHERE column != 'X'` 또는 `NOT IN`
- "X만" → `WHERE column = 'X'` 또는 `IN`

## 상대적 날짜 처리

| 사용자 표현 | SQL 변환 (오늘이 2026-02-10인 경우) |
|------------|-------------------------------------|
| 이번 달 | `EXTRACT(YEAR FROM Date) = 2026 AND EXTRACT(MONTH FROM Date) = 2` |
| 지난달 | `EXTRACT(YEAR FROM Date) = 2026 AND EXTRACT(MONTH FROM Date) = 1` |
| 올해 | `EXTRACT(YEAR FROM Date) = 2026` |
| 작년 | `EXTRACT(YEAR FROM Date) = 2025` |
| 최근 3개월 | `Date >= DATE_SUB(CURRENT_DATE(), INTERVAL 3 MONTH)` |
| 최근 6개월 | `Date >= DATE_SUB(CURRENT_DATE(), INTERVAL 6 MONTH)` |
| 전년 동기 대비 | 올해 vs 작년 같은 월/분기 비교 |

## 예시 쿼리 (SALES_ALL_Backup)

⚠️ SALES_ALL_Backup 기본 규칙: `Date >= '2019-01-01'` 전체 범위 금지 — 위 파티션 최적화 규칙에 따라 구체적 기간 조건 필수

### 1. 단순 매출 (제품 분해 X!)
```sql
-- "쇼피 인도네시아 이번 달 매출" → 제품 안 물어봄 = 총합만! (수량까지 물었으면 수량은 Product 서브쿼리로)
SELECT SUM(Sales1_R) AS total_revenue
FROM `skin1004-319714.Sales_Integration.SALES_ALL_Backup`
WHERE Country = '인도네시아' AND Mall_Classification LIKE '%Shopee%'
  AND EXTRACT(YEAR FROM Date) = 2026 AND EXTRACT(MONTH FROM Date) = 3
LIMIT 1000
```

### 2. 분기별 (⚠️ 분기 포맷!)

### 예시 쿼리
```sql
-- A1. 월별 전체 광고비
SELECT FORMAT_DATE('%Y-%m', date) AS month, SUM(cost_krw) AS cost
FROM `skin1004-319714.marketing_analysis.integrated_ad`
WHERE date BETWEEN '2025-01-01' AND '2025-12-31'
GROUP BY month ORDER BY month;

-- A2. 매체별 ROAS TOP 5
SELECT media,
       SUM(cost_krw) AS cost,
       SUM(conversion_value_krw) AS conv_value,
       SAFE_DIVIDE(SUM(conversion_value_krw), SUM(cost_krw)) AS roas
FROM `skin1004-319714.marketing_analysis.integrated_ad`
WHERE date >= DATE_SUB(CURRENT_DATE(), INTERVAL 3 MONTH)
GROUP BY media ORDER BY roas DESC LIMIT 5;

-- A3. Meta 광고 CTR 월별 추이
SELECT FORMAT_DATE('%Y-%m', date) AS month,
       SAFE_DIVIDE(SUM(clicks), SUM(impressions)) AS ctr
FROM `skin1004-319714.marketing_analysis.integrated_ad`
WHERE media = 'Meta' AND date BETWEEN '2025-01-01' AND '2025-12-31'
GROUP BY month ORDER BY month;

-- A4. 팀별 광고비 (2025년)
SELECT team, SUM(cost_krw) AS cost
FROM `skin1004-319714.marketing_analysis.integrated_ad`
WHERE date BETWEEN '2025-01-01' AND '2025-12-31'
GROUP BY team ORDER BY cost DESC;

-- A5. 국가별 전환수 (2026 Q1)
SELECT country, SUM(conversions) AS conversions
FROM `skin1004-319714.marketing_analysis.integrated_ad`
WHERE date BETWEEN '2026-01-01' AND '2026-03-31' AND country IS NOT NULL
GROUP BY country ORDER BY conversions DESC;

-- A6. 계정별 광고비 TOP 10
SELECT account_name, media, SUM(cost_krw) AS cost
FROM `skin1004-319714.marketing_analysis.integrated_ad`
WHERE date >= DATE_SUB(CURRENT_DATE(), INTERVAL 3 MONTH)
GROUP BY account_name, media ORDER BY cost DESC LIMIT 10;

-- A7. 매체 × 국가 ROAS 매트릭스
SELECT media, country,
       SAFE_DIVIDE(SUM(conversion_value_krw), SUM(cost_krw)) AS roas
FROM `skin1004-319714.marketing_analysis.integrated_ad`
WHERE date >= DATE_SUB(CURRENT_DATE(), INTERVAL 1 MONTH)
      AND country IS NOT NULL
GROUP BY media, country ORDER BY roas DESC;

-- A8. YoY 광고비 성장률 (매체별)
WITH cur AS (
  SELECT media, SUM(cost_krw) AS cost
  FROM `skin1004-319714.marketing_analysis.integrated_ad`
  WHERE EXTRACT(YEAR FROM date) = 2026 GROUP BY media
), prev AS (
  SELECT media, SUM(cost_krw) AS cost
  FROM `skin1004-319714.marketing_analysis.integrated_ad`
  WHERE EXTRACT(YEAR FROM date) = 2025 GROUP BY media
)
SELECT cur.media, cur.cost AS cur_cost, prev.cost AS prev_cost,
       SAFE_DIVIDE(cur.cost - prev.cost, prev.cost) AS yoy_growth
FROM cur LEFT JOIN prev USING(media) ORDER BY yoy_growth DESC;
```

### Channel 실제 DISTINCT 값 (19개, 정확한 값)

- ⚠️ '아마존 AU'가 실제 값 ('AU아마존' 아님!), 'LW Cosmetocs'가 실제 값 (오타 포함)

### 순위 변동 분석 패턴 (핵심!)
```sql
-- 최근 1주 vs 이전 1주 순위 비교 → 상승폭 TOP N
WITH recent AS (
  SELECT Brand_Name, Product_Name, AVG(Rank) AS avg_rank_recent
  FROM `skin1004-319714.Platform_Data.raw_data`
  WHERE Channel = '예스스타일'
    AND DATE(Date) >= DATE_SUB(CURRENT_DATE(), INTERVAL 7 DAY)
  GROUP BY Brand_Name, Product_Name
),
prev AS (
  SELECT Brand_Name, Product_Name, AVG(Rank) AS avg_rank_prev
  FROM `skin1004-319714.Platform_Data.raw_data`
  WHERE Channel = '예스스타일'
    AND DATE(Date) >= DATE_SUB(CURRENT_DATE(), INTERVAL 14 DAY)
    AND DATE(Date) < DATE_SUB(CURRENT_DATE(), INTERVAL 7 DAY)
  GROUP BY Brand_Name, Product_Name
)
SELECT r.Brand_Name, r.Product_Name,
  ROUND(p.avg_rank_prev, 1) AS prev_rank,
  ROUND(r.avg_rank_recent, 1) AS recent_rank,
  ROUND(p.avg_rank_prev - r.avg_rank_recent, 1) AS rank_improvement
FROM recent r JOIN prev p ON r.Brand_Name = p.Brand_Name AND r.Product_Name = p.Product_Name
WHERE p.avg_rank_prev > r.avg_rank_recent
ORDER BY rank_improvement DESC
LIMIT 10
```

### 규칙
- ⚠️ Brand_Name은 **대문자**: `Brand_Name = 'SKIN1004'` ✅ (소문자 금지!)
- 날짜 필터 필수: `DATE(Date) >= ...`
- 순위 분석: AVG(Rank) 집계 사용 (일별 변동)
- 채널명 정확히 사용: `Channel = '예스스타일'` ✅ (YesStyle ❌)
- `LIMIT 500` 이하
- "순위 상승" = 이전 기간 Rank가 높은 숫자(하위)에서 최근 낮은 숫자(상위)로 이동한 것

### 사용자가 팀-국가 매핑을 명시한 경우 — CASE WHEN으로 팀 분류 가능!

사용자가 "EAST1 - 인도네시아, 필리핀 / EAST2 - 말레이시아, 싱가포르 / WEST - 미국, 호주, 영국, 멕시코, 폴란드 / JBT - 일본 / KBT - 한국" 처럼 팀-국가 매핑을 명시하면 CASE WHEN으로 팀 컬럼 생성 가능.

**주의: 언어 불일치**
- `meta data_test`.country_name = 영어 ('Indonesia', 'South Korea', 'Japan', 'United States', 'United Kingdom', 'Australia', ...)
- `SALES_ALL_Backup`.Country = 한국어 ('인도네시아', '한국', '일본', '미국', '영국', '호주', ...)
- 두 테이블을 JOIN할 때 country 기준 JOIN은 불가. **월별 합산 후 팀별 합계**만 가능.

```sql
-- 팀별 메타광고 소재수 + 매출 효율 (사용자 명시 팀-국가 매핑 기준)
WITH meta_team AS (
  SELECT
    FORMAT_DATE('%Y-%m', DATE(start_date_formatted)) AS month,
    CASE
      WHEN country_name IN ('Indonesia', 'Philippines') THEN 'EAST1'
      WHEN country_name IN ('Malaysia', 'Singapore') THEN 'EAST2'
      WHEN country_name IN ('United States', 'Australia', 'United Kingdom', 'Mexico', 'Poland') THEN 'WEST'
      WHEN country_name = 'Japan' THEN 'JBT'
      WHEN country_name = 'South Korea' THEN 'KBT'
      ELSE 'OTHER'
    END AS team,
    COUNT(DISTINCT ad_archive_id) AS creative_count
  FROM `skin1004-319714.ad_data.meta data_test`
  WHERE brand = 'skin1004'
    AND DATE(start_date_formatted) >= '2026-01-01'
  GROUP BY month, team
),
sales_team AS (
  SELECT
    FORMAT_DATE('%Y-%m', Date) AS month,
    CASE
      WHEN Country IN ('인도네시아', '필리핀') THEN 'EAST1'
      WHEN Country IN ('말레이시아', '싱가포르') THEN 'EAST2'
      WHEN Country IN ('미국', '호주', '영국', '멕시코', '폴란드') THEN 'WEST'
      WHEN Country = '일본' THEN 'JBT'
      WHEN Country = '한국' THEN 'KBT'
      ELSE 'OTHER'
    END AS team,
    SUM(Sales1_R) AS total_sales
  FROM `skin1004-319714.Sales_Integration.SALES_ALL_Backup`
  WHERE Brand IN ('SK', 'CL')
    AND Date >= '2026-01-01'
  GROUP BY month, team
)
SELECT
  m.month,
  m.team,
  m.creative_count,
  s.total_sales,
  ROUND(s.total_sales / NULLIF(m.creative_count, 0), 0) AS sales_per_creative
FROM meta_team m
LEFT JOIN sales_team s ON m.month = s.month AND m.team = s.team
WHERE m.team != 'OTHER'
ORDER BY m.month, m.team
LIMIT 200
```

```sql
  Mall_Classification,
  COUNT(DISTINCT ID) AS total_customers,
  COUNT(DISTINCT CASE WHEN order_days >= 2 THEN ID END) AS repeat_customers,
  ROUND(COUNT(DISTINCT CASE WHEN order_days >= 2 THEN ID END) * 100.0
        / NULLIF(COUNT(DISTINCT ID), 0), 1) AS repurchase_rate_pct
FROM customer_orders
GROUP BY month, Mall_Classification
ORDER BY month, Mall_Classification
```

### 규칙
- 재구매 = 같은 기간 내 2회 이상 구매한 고객 (ID 기준)
- Brand IN ('SK', 'CL') 필터 필수
- ⛔ SALES_repurchase 테이블 사용 금지! SALES_ALL_Backup만 사용!

## 테이블 14: FI_LLM_Flat (재무 손익 — 이익/원가/판관비) ⭐ LONG 포맷

테이블: `skin1004-319714.Sales_Integration.FI_LLM_Flat`

**특징**: 재무 연결손익 기준 **월 단위 확정 손익**. 한 행 = 하나의 금액 (long format, `Record_Type, Year_Month, Country, Item` 클러스터링).
- **영업이익, 매출총이익, 매출원가, 판관비, 이익률, 계정과목(광고선전비 등), 부서/본부별 손익 질문은 무조건 이 테이블!**
- 단순 "매출" 질문은 기존대로 `SALES_ALL_Backup` (일별/주문 단위). 단, 이익률 계산처럼 매출과 이익을 함께 쓸 때는 FI_LLM_Flat 안에서 매출액·이익을 같이 조회 (테이블 간 혼합 금지 — 기준이 달라 숫자 안 맞음)
- 일별 데이터 없음! 월 단위(Year_Month)가 최소 단위
- ⚠️ **보유 기간: 2026-01 ~ 2026-06 (6개월치뿐)**. 이 범위 밖(작년·재작년 등)을 묻는 경우
  빈 결과만 돌려주지 말고 "재무 손익 데이터는 2026년 1~6월만 보유 중"이라고 먼저 안내한 뒤
  가능한 기간으로 다시 제안할 것. (매출·수량은 SALES_ALL_Backup 에 과거 데이터가 있으므로
  이 제약은 손익 질문에만 해당)

### ⛔ Record_Type — 모든 쿼리에 필수 필터! (섞어서 SUM하면 판관비 이중집계)

| 값 | 내용 | 신뢰도 |
|----|------|--------|
| `'PL'` | 손익 실적. `Item` = '매출액'/'매출원가'/'매출총이익'/'판관비'/'영업이익'/'판매수량' | 확정치 |
| `'SGA_DETAIL'` | 판관비 계정과목별 상세. `Item` = 전체 계정과목명 (예: '(판)광고선전비(페이드 마케팅_해외)') | **추정치** (부서×월 판관비 구성비로 비례배분) |

### 컬럼 스키마

| 컬럼 | 타입 | 설명 |
|------|------|------|
| Record_Type | STRING | 'PL' / 'SGA_DETAIL' ⛔ 필수 필터 |
| Item | STRING | PL: 손익 항목명(한국어) / SGA_DETAIL: 계정과목명 |
| Amount | FLOAT | 금액(원). Item='판매수량' 행만 수량 |
| Year_Month | STRING | **'YYYY-MM' 문자열** ⚠️ DATE 아님! `= '2026-06'` 또는 `LIKE '2026-%'` 사용, EXTRACT/DATE 함수 금지 |
| Country / Continent1 / Continent2 | STRING | 국가(한국어) / 권역 / 대륙 |
| Sales_Type | STRING | 'B2B' / 'B2C' |
| Channel | STRING | 거래처/채널명 |
| Brand | STRING | 'SK'(스킨1004) 등 |
| Division / Department | STRING | 본부 / 부서 |
| Team | STRING | 팀 (SGA_DETAIL 전용) |
| Line / Category / Product_Name / Product_Code | STRING | 제품 계층 ⚠️ Brand='SK'만 유효 (제품 분석 시 `Brand='SK'` 필터) |
| Adjustment_Type | STRING | PL 전용: '일반' / '연결조정' / '내부마진' |
| SM_Main_Category | STRING | 계정 **대분류**: '광고선전비'/'물류비'/'수수료'/'인건비'/'기타' ⭐ "광고선전비 얼마?" → 이 컬럼! |
| SM_Sub_Category | STRING | 계정 중분류 (광고선전비/운반비/수출경비/판매수수료/지급수수료/급여 등) |
| SM_Detail_Category | STRING | 계정 소분류 (페이드 마케팅_해외/인플루언서 마케팅/관세 등) |
| Cost_Class | STRING | '판매직접' / '판매간접' |
| Is_Estimated | BOOL | SGA_DETAIL이면 TRUE |

### 규칙
1. 손익 항목(매출액·영업이익 등) → `WHERE Record_Type='PL' AND Item='영업이익'` (Item 정확 일치, 한국어)
2. 계정과목(광고선전비 등) → `WHERE Record_Type='SGA_DETAIL' AND SM_Main_Category='광고선전비'` ⛔ `Item='광고선전비'` 정확 일치는 0건! 반드시 SM_Main_Category/SM_Sub_Category 사용
3. 이익률 = `SAFE_DIVIDE(SUM(IF(Item='영업이익', Amount, 0)), SUM(IF(Item='매출액', Amount, 0)))` 패턴 (같은 Record_Type='PL' 안에서)
4. 회사 전체 손익 = Adjustment_Type 전체 포함(연결 기준). "조정 제외" 요청 시만 `Adjustment_Type='일반'`
5. 계정과목 상세는 추정치 — 답변에 "비례배분 추정치" 명시 권장

### 예시 쿼리
```sql
-- "일본 올해 월별 영업이익이랑 영업이익률"
SELECT Year_Month,
  SUM(IF(Item='매출액', Amount, 0)) AS sales,
  SUM(IF(Item='영업이익', Amount, 0)) AS op_income,
  ROUND(SAFE_DIVIDE(SUM(IF(Item='영업이익', Amount, 0)), SUM(IF(Item='매출액', Amount, 0))) * 100, 1) AS op_margin_pct
FROM `skin1004-319714.Sales_Integration.FI_LLM_Flat`
WHERE Record_Type='PL' AND Country='일본' AND Year_Month LIKE '2026-%'
GROUP BY Year_Month ORDER BY Year_Month LIMIT 1000

-- "일본 광고선전비 B2B/B2C 얼마씩?"
SELECT Sales_Type, SUM(Amount) AS ad_expense
FROM `skin1004-319714.Sales_Integration.FI_LLM_Flat`
WHERE Record_Type='SGA_DETAIL' AND SM_Main_Category='광고선전비' AND Country='일본'
GROUP BY Sales_Type LIMIT 1000
```

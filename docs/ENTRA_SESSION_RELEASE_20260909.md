기존 비밀번호 로그인 API는 닫혀 있었지만, 인증 출처가 없는 과거 JWT 쿠키가 `/me`에서 계속 갱신되는 문제가 있었다. Entra 연결된 계정의 과거 쿠키도 같은 문제를 가졌다. 이제 검증된 Entra 콜백이 발급한 세션의 provider·tenant·oid를 확인하며, 계정 존재나 디렉터리 연결 기록으로 인증을 승격하지 않는다. 기존 사용자는 Entra로 한 번 다시 로그인해야 한다.

- 관리자 표시는 `Entra 로그인 완료 / Entra 로그인 필요` 하나로 정리했다. 완료는 Entra 연결·셀라 계정·Entra 로그인 기록이 모두 있는 경우다.
- `/me`는 검증된 현재 요청의 인증 증명만 갱신한다. 사용자 캐시가 있어도 과거·비밀번호·다른 용도의 JWT는 차단한다.
- 공통 미들웨어가 앱 화면과 API를 보호한다. 미인증 API는 `401`과 `X-Cella-Auth: login-required`, 화면은 로그인 이동으로 응답한다.
- 열려 있는 화면에서 표시된 인증 실패를 받으면 로그인으로 이동한다. 작성 중 질문은 같은 사용자가 다시 로그인한 경우에만 복원하며 자동 전송하지 않는다. Google 등 외부 서비스 자체의 401은 로그아웃으로 오인하지 않는다.
- 내부 골든셋·자가 점검은 별도 서비스 토큰으로 직접 loopback의 채팅 점검 경로만 이용한다. 프록시 요청·관리자 API·세션 갱신에는 쓸 수 없다.
- 로그인 시작·두 Entra 콜백·Google 콜백·헬스·로그인 자산은 기존 흐름을 유지한다. 잔디 릴레이 경로는 기존 자체 인증을 유지한다.

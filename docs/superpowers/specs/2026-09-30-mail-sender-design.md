# 메일 자동 발송 전용 페이지 (`/mail-sender`) — 설계

**작성일**: 2026-09-30 · **상태**: 결정·전제 확인 완료(2026-10-01) → 구현 계획 작성
**요청**: 마케팅팀이 쓰는 "Gmail 대량 발송" Apps Script 툴(gmailv2)을 셀라 안의 전용 탭으로
옮긴다. 인증서류 찾기(`/coa-finder`)와 같은 구조 — 사이드바 버튼 → 새 탭 → 본인 구글 권한으로 동작.

---

## 왜 만드나

지금 툴은 스프레드시트에 붙은 Apps Script 다 (`gmail_v2` 시트 → 확장 프로그램 → 메뉴 `📧 메일 발송`).
노션 가이드 "DM/Mail 자동화가이드 1-3" 대로 수십 명이 쓴다. 2026-09-28~30 사이에 실제로 난 사고:

| 사고 | 원인 | 근거 |
|---|---|---|
| 받는 쪽에서 이미지가 엑스박스 | Docs API `contentUri`(임시 링크)를 `<img src>` 로 그대로 보냄. 42분 지난 링크로 보낸 메일에서 3장 중 2장 깨짐 재현 | 2026-09-28 실측 |
| 전체 발송이 30분에 조용히 끊김 | Apps Script 실행 한도 30분. 9/22 3건·9/28 1건 `시간이 초과되었습니다` | 실행 기록 |
| Docs 를 읽다 메모리 부족 | 템플릿 문서 탭 99개. 전체 로딩 83초, 두 번 읽으면 OOM | 2026-09-29 실측 |
| 권한 일부만 허용한 사용자의 전 행이 X | 구글 세분화 동의 화면에서 "외부 서비스 연결"을 안 켬 → `UrlFetchApp` 권한 오류가 행마다 기록 | 2026-09-30 서구권마케팅팀 제보 |
| 탭 없음 오류에 "가능:" 목록이 빈 채로 나옴 | `includeTabsContent` 없이 조회하면 `doc.tabs` 가 비어 있음 | 2026-09-29 수정 |

Apps Script 로는 **실행 시간 한도·미리보기 없음·발송 전 점검 없음**을 근본적으로 못 푼다.
서버에서 돌면 셋 다 풀린다.

## 결정 사항 (2026-09-30 사용자 확정)

| 항목 | 결정 |
|---|---|
| 붙일 자리 | **전용 페이지** `/mail-sender`, 사이드바 버튼 (인증서류 찾기와 같은 구조) |
| 발송 주체 | AI Agent 가 **직접 발송** (사용자 본인 구글 계정으로) |
| 입력 | 기존 그대로 — 템플릿은 Google Docs(담당자별 탭), 수신자는 `gmail_` 시트 |
| 진행 | 설계 문서 → 전제 확인 → 점검·미리보기 → 발송 순 |
| 사용 대상 | **로그인한 사용자 전체** (그룹 관문 없음) |
| 보내는 주소 | **본인 주소 + 공용 주소 둘 다** — 공용은 Gmail "다른 주소에서 보내기"(Send As) 별칭으로 (아래 참조) |
| 기존 Apps Script 툴 | **병행 사용** (막지 않는다) — 같은 시트 중복 발송 방지가 필요 (아래 참조) |
| 한 작업 최대 건수 | **제한 없음** — 단, 계정 일일 발송 한도 점검은 유지 |

## 원칙

- ⛔ **LLM 을 부르지 않는다.** 템플릿 치환·검증·발송은 전부 규칙이다 (인증서류·매출 이월과 같은 사상).
  메일은 밖으로 나가는 산출물이라 모델이 문장을 바꾸면 안 된다
- ⛔ **확인 없이 보내지 않는다.** 전체 발송은 수신자 수·제목·첫 수신자 미리보기를 보여주고
  사용자가 누른 뒤에만 시작한다. 채팅 경로(오케스트레이터 게이트)로는 발송을 열지 않는다
- ⛔ **같은 사람에게 두 번 보내지 않는 것이 실패보다 중요하다.** 애매하면 멈추고 사람에게 넘긴다
  (재시작 후 자동 재개 금지 — 아래 참조)
- ⛔ **권한·토큰 문제를 발송 결과로 만들지 않는다.** 발송 전에 잡는다. 오늘처럼 N행 전부 X 가 되면
  사람이 원인을 행마다 읽어야 한다

## 흐름 (화면 한 장, 단계 5개)

1. **불러오기** — 스프레드시트 링크 붙여넣기 → `gmail_` 로 시작하는 시트 목록에서 선택
2. **점검** — 발송 없이 행마다 ✅/⚠️/❌ (아래 "점검 항목"). 지금의 `템플릿 검증` 메뉴를 대체
3. **미리보기** — 수신자를 골라 치환된 제목·본문·이미지를 실제 메일 모양으로 본다
4. **테스트 발송** — **로그인한 본인 주소로만** 1통. 시트에 기록하지 않는다
5. **전체 발송** — 확인 창(`N명 · 담당자 탭 · 제목`) → 서버 작업 시작 → 진행률.
   창을 닫아도 계속되고, 다시 열면 진행 중인 작업을 보여준다. 끝나면 요약 + 실패 행만 재발송

### 점검 항목

| 항목 | 판정 |
|---|---|
| 담당자(B열) 값에 맞는 Docs 탭이 있다 | 없으면 ❌ + **실제 탭 이름 목록**과 가장 비슷한 이름 제시 (공백 차이 포함) |
| 탭 첫 줄이 `제목:` 으로 시작 | 없으면 ❌ |
| 템플릿의 `{변수}` 가 시트 헤더에 모두 있다 | 없으면 ❌ (대소문자 무시·공백 허용은 기존 규칙 그대로) |
| 이메일 형식 | 형식 오류 ❌ |
| 같은 시트 안 중복 이메일 | ⚠️ (보내긴 하지만 알린다) |
| 이미 `O` 인 행 | 제외 대상으로 표시 (재발송하려면 사용자가 명시적으로 고른다) |
| 이미지 받아오기 | 템플릿의 이미지를 실제로 받아 본다. 실패하면 ❌ (지금의 엑스박스 사고를 발송 전에 잡는다) |
| 예상 메일 크기 | 이미지 합계가 크면 ⚠️, Gmail 한도(25MB) 근처면 ❌ |
| 오늘 남은 발송 한도 | 대상 수가 계정 일일 한도(Workspace 약 2,000)를 넘으면 ❌ |

## 템플릿 읽기 — 탭 목록(시트) + 탭별 내보내기(B안, 2026-10-01 확정)

**Docs API 를 쓰지 않는다.** WAS 에서 `docs.googleapis.com`·`*.googleusercontent.com` 이 프록시에 막혀 있고,
GCP 프로젝트(`skin1004-319714`)에서 Docs API 가 꺼져 있으며 우리 계정에 켤 권한이 없다 (아래 실측).
대신 **이미 열려 있는 경로만** 쓴다.

```
[gmailv2 Apps Script]  DocumentApp 으로 탭 목록을 읽어
        └─ gmail_v2 시트의 숨김 탭 `_탭목록` 에 기록 (탭 제목 · 탭 ID · 상위 탭 · 갱신 시각)
              ↑ 10분 시간 트리거 + `템플릿 검증` 메뉴 실행 시
[WAS]  Sheets API 로 `_탭목록` 읽기 → 담당자(B열) → 탭 ID
       docs.google.com/document/d/{DOC_ID}/export?format=zip&tab={탭 ID}   (사용자 토큰, drive.readonly)
       └─ zip = HTML 1개 + images/ (이미지가 **파일로** 들어 있다 → googleusercontent 접속 불필요)
```

실측 (2026-09-30): 탭 `t.0` 내보내기 → 200 · zip 14.7MB · HTML + 이미지 19개.
문서 **전체** 내보내기(Drive `files.export`)는 `exportSizeLimitExceeded`(10MB 한도)로 실패 — 탭별로만 된다.

- 탭 목록이 Apps Script 에 의존하므로 **목록이 낡을 수 있다.** 방금 만든 탭은 최대 10분 늦게 보인다 →
  "탭 없음" 판정 옆에 `_탭목록` 갱신 시각과 "방금 만든 탭이면 잠시 뒤 다시" 를 적는다
- ⛔ 갱신 시각이 오래됐으면(예: 1시간 초과) 점검 단계에서 경고 — 트리거가 죽은 것을 "탭 없음" 으로 보이게 두지 않는다
- 작업 하나당 담당자 탭마다 **한 번만** 내보내고 작업 동안 재사용한다

### 내보낸 HTML → 메일 HTML

내보내기 HTML 은 구글이 만든 것이라 **gmailv2 변환 결과와 다르다.** 대신 원본 Docs 모양에 더 가깝다.

- 한글이 `&#51228;` 같은 숫자 엔티티로 들어 있다 — `제목:` 줄을 찾기 전에 디코드한다
- 서식이 `<head><style>` 의 클래스(`.c12` 등, 실측 74KB)로 걸려 있다 — Gmail 은 `<style>` 을 부분적으로만
  지원하므로 **클래스를 인라인 `style=""` 로 펼친다** (premailer 류, 쓰는 속성만 남긴다)
- 첫 줄 `제목:` 문단 → 메일 제목, 그 문단은 본문에서 뺀다 (기존 규칙과 같다)
- 이미지 `<img src="images/imageN.png">` → `cid:` 로 바꾸고 zip 안 파일을 인라인 첨부
- 문서 여백·페이지 폭 스타일(`max-width` 등)은 버린다 — 메일에서 본문이 좁아진다
- ⚠️ **Enter/Shift+Enter 간격이 기존과 달라질 수 있다.** 기존은 `<br><br>` 로 직접 만들었고, 내보내기는
  `<p>` 여백을 쓴다. 가이드의 "줄바꿈 주의사항" 을 그대로 지켰을 때 같은 모양인지 확인한다

**비교 회귀 (골든 대신)**: 바이트 동일은 목표가 아니다. 대표 탭 10개를 gmailv2(기존)·새 방식 둘 다로
본인에게 보내 **나란히 눈으로 확인**하고, 자동 검사는 다음만 본다 —
텍스트(태그 제거 후)가 같다 · 굵게/기울임/밑줄/링크 개수가 같다 · 이미지 수가 같다 · 외부 이미지 URL 이 0개

## 발송 작업 — 백그라운드

- 작업(job)과 행(item)을 MariaDB 에 적는다: `mail_send_jobs`(시트·작성자·상태·총/성공/실패),
  `mail_send_items`(행 번호·이메일·상태·오류·보낸 시각·Gmail message id)
- 행마다: **발송 직전에 그 행의 G열을 다시 읽어** 이미 `O` 면 건너뜀 → 발송 → 성공이면 **즉시** 시트 G열 `O`·
  A열 날짜 기록 → 다음 행. 발송 간격은 기존과 같은 1초
  (기존 Apps Script 툴과 병행하므로 — 작업 시작 시점의 목록을 믿으면 그 사이 다른 툴이 보낸 행을 또 보낸다)
- 한 작업 건수 제한은 없다. 대신 시작 전에 일일 한도 대비 건수를 점검하고, 한도 오류가 나면 멈춘다
- **중지** 버튼 — 현재 행까지 보내고 멈춘다
- ⛔ **서버가 재시작되면 작업을 자동으로 이어 보내지 않는다.** `중단됨` 으로 두고, 마지막으로
  발송 요청했지만 결과를 못 적은 행을 `확인필요` 로 표시한다. 사용자가 보낸편지함을 확인하고 재개한다
  (그 행이 실제로 나갔는지 서버는 모른다 — 자동 재개하면 중복 발송이 난다)
- 같은 시트에 진행 중인 작업이 있으면 새 작업을 거부한다
- ⛔ `ThreadPoolExecutor` 를 `with` 로 감싸지 않는다 (프로젝트 규칙)

## 권한 — 구글 OAuth

| 스코프 | 용도 |
|---|---|
| `gmail.send` | 본인 계정으로 발송 |
| `spreadsheets` | 수신자·`_탭목록` 읽기 + 결과(O/X·날짜·비고) 쓰기 |
| (기존) `drive.readonly` | 탭별 내보내기 — **이미 받고 있다**, 추가 아님 (2026-09-30 실측으로 확인) |

Docs 전용 스코프(`documents.readonly`)는 필요 없다 (Docs API 를 쓰지 않으므로).

- **증분 동의로 받는다** (`include_granted_scopes=true`). 메일 페이지에 처음 들어온 사람에게만
  추가 권한을 요청한다 — 전체 스코프 목록에 넣어 버리면 **인증서류 찾기만 쓰는 사람까지** 재동의하게 된다
- ⛔ **콜백에서 실제로 받은 스코프를 확인한다.** 세분화 동의 화면에서 일부만 켜고 허용할 수 있다
  (2026-09-30 사고). 빠진 스코프가 있으면 발송 화면 대신 "무엇이 빠졌는지 + 다시 연결" 을 보여준다
- 발송 계정 = 연결된 구글 계정. 셀라 로그인 계정과 다르면 화면 맨 위에 **보내는 주소를 크게** 적는다
- 접근 권한: **로그인한 사용자 전체** (브랜드·그룹 관문 없음)

### 보내는 주소 — 본인 + 공용 (Send As 별칭)

- 불러오기 단계에서 **보내는 주소를 고른다.** 목록 = 본인 주소 + 그 계정에 등록·인증된
  "다른 주소에서 보내기" 별칭 (`users.settings.sendAs.list`, `verificationStatus=accepted` 만)
- 공용 주소(예: marketing@)로 보내려면 **그 사람 Gmail 에 해당 주소가 별칭으로 등록돼 있어야 한다.**
  목록에 없으면 "Gmail 설정 → 계정 → 다른 주소에서 메일 보내기" 안내를 보여준다 (셀라가 대신 등록하지 않는다)
- 발송은 MIME `From:` 에 고른 별칭을 넣어 본인 토큰으로 보낸다. 보낸편지함은 본인 계정에 남는다
- ⛔ 목록에 없는 주소를 `From:` 에 넣지 않는다 — 구글이 본인 주소로 바꿔 보내서 **공용으로 보낸 줄 알았는데
  개인 주소로 나가는** 조용한 실패가 된다. 서버가 발송 직전에 다시 대조한다
- 답장은 그 별칭의 "답장 받을 주소" 설정을 따른다 (화면에 표시)
- ⚠️ 공용 **계정** 자체에 로그인해 보내는 방식(공용 계정 토큰 보관·대리 발송)은 이번 범위 밖 —
  토큰을 누가 연결·관리하는지부터 정해야 한다. 필요해지면 따로 설계한다
- ⚠️ 확인할 것: `sendAs.list` 가 기존 `gmail.readonly` 스코프로 되는지 (안 되면 `gmail.settings.basic` 추가)
- 새 화면은 `middleware._page_request` 목록에 넣는다 (매출 이월에서 한 번 빠뜨렸다)

## 먼저 확인할 가정 (구현 첫 단계)

1. ⚠️ **WAS(10.1.150.5)에서 `gmail.googleapis.com`·`docs.googleapis.com`·`sheets.googleapis.com` 으로 나가는지.**
   `www.googleapis.com` 은 브리핑이 도는 것으로 간접 확인됐지만 이 셋은 따로 찔러 본다. 발송은 이미지가 붙어
   요청이 크므로 **수 MB 업로드**도 확인한다 (프록시 `10.1.50.2:3128`)
2. ⚠️ **OAuth 동의 화면이 조직 내부(Internal) 앱인지.** 외부(External)면 `gmail.send`·`spreadsheets` 는
   민감 스코프라 구글 검수가 필요하다
3. ⚠️ **OAuth 리다이렉트 URI 가 WAS 도메인으로 등록돼 있는지** (증분 동의 콜백)
4. ⚠️ Gmail API 발송 크기 한도 — 이미지가 많은 템플릿(실측 78장)이 한 요청으로 나가는지.
   안 되면 업로드 방식(`media` 업로드)으로 보낸다

여기서 1·2 가 막히면 나머지 설계가 의미 없다 — 먼저 찔러 본다.

### 실측 결과 — WAS 프록시 (2026-09-30, `curl -v` 로 CONNECT 응답 확인)

| 대상 | 결과 | 뜻 |
|---|---|---|
| `www.googleapis.com` (Drive 등) | ✅ 터널 200 | 통과 |
| `oauth2.googleapis.com` | ✅ 404 | 통과 (토큰 갱신 가능) |
| `gmail.googleapis.com` | ✅ 401 · **12MB 업로드도 401** | 통과 — 이미지 붙은 큰 메일도 프록시를 지난다 |
| `sheets.googleapis.com` | ✅ 터널 200 → 구글 403(인증 없음) | 통과 |
| `docs.googleapis.com` | ❌ **프록시 CONNECT 403** | **막힘** — 템플릿을 못 읽는다 |
| `lh7-rt.googleusercontent.com` · `lh3.googleusercontent.com` | ❌ **프록시 CONNECT 403** | **막힘** — Docs 이미지(`contentUri`)를 못 받는다 |

- `www.googleapis.com/docs/v1/...` 로 우회되지 않는다 (404). Docs API 는 `docs.googleapis.com` 전용이다
- ⛔ **Drive `export`(zip/html) 로 우회하지 않는다** — HTML 이 Apps Script 변환 결과와 달라져
  "기존 서식 그대로" 가 깨지고, 탭 구조를 잃는다
- 추가 실측: `docs.google.com`·`drive.google.com` ✅ 열림 / `script.googleapis.com`·`script.google.com`·
  `script.googleusercontent.com`·`content.googleapis.com` ❌ 막힘
- GCP 프로젝트 953100330779(`skin1004-319714`)에서 **Docs API 가 꺼져 있다**(`SERVICE_DISABLED`),
  jeffrey 계정에 `serviceusage.services.enable` 권한이 없어 켤 수 없다
- 브라우저 → `docs.googleapis.com` CORS 프리플라이트는 `http://10.1.100.5` 를 허용한다 (참고용, 지금은 안 쓴다)
- → **IT 요청·GCP 변경 없이 가는 B안 채택** (위 "템플릿 읽기"). 나중에 Docs API·프록시가 열리면
  탭 목록만 Docs API 로 바꾸면 된다
- 2 ✅ **OAuth 앱 사용자 유형 = 내부(Internal)** (2026-10-01 콘솔 "Google 인증 플랫폼 → 대상" 확인) —
  `gmail.send`·`spreadsheets` 에 구글 검수가 필요 없다
- 3 ✅ 리다이렉트 URI 는 요청 호스트로 동적으로 정해진다 (`google_auth.py:311-351`). 운영에서 인증서류 찾기의
  구글 연결이 같은 콜백으로 돌고 있으므로 증분 동의도 같은 경로를 탄다 — 새 등록 불필요
- 4(Gmail 발송 크기) — 프록시는 12MB 업로드를 통과시켰다. Gmail API 쪽 한도는 구현 때 실제 발송으로 확인
- **→ 전제 확인 끝. 남은 위험은 "내보내기 HTML 의 서식 차이" 하나 — 첫 구현 단계에서 비교 발송으로 본다**

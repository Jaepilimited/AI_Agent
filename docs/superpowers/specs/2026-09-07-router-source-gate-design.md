# 라우터 1단계 — "소스가 필요한가?" 판정

**작성** 2026-09-07 · **상태** 설계 승인됨, 구현 대기
**계기** 붐따 #163·#164 (김미이, 2026-09-04) + 그날의 확신 관문 전수 감사

---

## 1. 왜

라우터는 **"소스를 쓰는 것이 기본"** 이고 `direct` 는 아무 데도 안 걸렸을 때
떨어지는 폴스루다. 반환 지점 26개 중 direct 는 5개뿐이고, 그나마 인사말·외부
주제 같은 열거형 예외다.

자유도가 높은 질문은 정의상 아무 목록에도 안 걸린다. 그런데 안 걸리면 direct 로
가는 것이 아니라, `노션 + 데이터 낱말 부재` 같은 **약한 근거의 가지**가 먼저
낚아챈다. 실측(2026-09-07, 실사용 60일 1,295건):

| 관문 | 결정 | 오분류 | 그 관문이 받는 질문 |
|---|---:|---:|---|
| `_DOC_WORD` | 18 | 0 | 「문서 찾아줘」 — 모양이 뚜렷 |
| cs | 126 | 4 | 「제품 특징」 — 뚜렷 |
| `has_team and not has_data` | 32 | 4 | 팀 + 절차 — 뚜렷 |
| **`_NOTION_KEYWORDS` + `not has_data`** | **9** | **7** | **아무 모양도 없는 것** |

**오류율은 질문에 모양이 있느냐에 반비례한다.** 김미이 님의 두 질문이 마지막
행에 걸린 것은 우연이 아니다 — 그 가지가 「아무 데도 안 걸린 것」을 받는 자리다.

### 사용자가 실제로 겪은 것

```
15:07  "셀라야 … 이제 개인노션 만들고야"          → CS 티트리카 문서
15:08  "아니 ;; 내 개인 업무 노션 ;;"            → 영업2팀 신규 입사자 문서
15:08  "아니 ㅠㅠㅠ … 제안해달라고!!!!!"           → ERP 기안 가이드
15:09  "너 진자 붐따임"
15:10  (검색 없이 답하자 원하던 구성안이 나왔다)
```

자료가 없어서가 아니라 **엉뚱한 곳을 뒤져서** 못 답했다.

## 2. 목표와 비목표

**목표**
- 사내 자료가 필요 없는 질문에 사내 자료를 뒤지지 않는다.
- 회사와 무관한 일반 질문(코드·번역·문장 다듬기)도 받는다 — 사용자 결정,
  2026-09-07.
- **사내 데이터가 우선이다.** 애매하면 뒤지는 쪽으로 기운다.
- 지금 잘 되고 있는 경로(실사용 77%)를 흔들지 않는다.

**비목표**
- 관문을 통째로 걷어내지 않는다. 오늘 감사에서 대부분 정확했다.
- 무조건 되묻지 않는다. 되묻기는 **진짜 애매할 때만** (사용자 지시).
- 되묻기를 SELF 판정 전반에 걸지 않는다 — "파이썬 코드 짜줘" 에 되물으면 안 된다.

## 3. 설계

```
0단계  @@ 소스 지정 · 붙여넣은 데이터            → 지금과 동일
1단계  키워드 관문이 **확신**하는가?
         예   → 그 경로로 간다 (LLM 호출 없음, 0초)     ← 실사용 77%
         아니오 → 2단계
2단계  Flash 에 **예/아니오 하나만** 묻는다
         "이 질문은 사내 자료를 뒤져야 답할 수 있는가?"   ← 0.83초
         NEED → 지금의 6지선다 분류로 소스를 고른다
         SELF → 소스를 쓰지 않고 바로 답한다
3단계  발화 첫머리가 **부정**이면 경로 상속을 끊고 다시 분류한다
4단계  부정인데 정보가 없으면 **되묻는다**
```

### 3.1 왜 예/아니오인가 (실측)

같은 모델·같은 질문 16문항:

| 묻는 방식 | 정확도 | 대표 오답 |
|---|---|---|
| 지금: "어느 소스냐" (6지선다) | #164 오답 | `노션` 낱말에 끌려 notion |
| 바꿈: "뒤져야 하나" (예/아니오) | **14/16** | 「노션 사용법」→SELF (위험한 방향) |

6지선다는 **"소스 중 하나여야 한다"를 전제**하고 있어 소스가 필요 없는 질문에
답이 없다. 예/아니오를 먼저 끼우면 그 전제가 사라진다.

⚠️ 예/아니오의 유일한 위험한 오답(「노션 사용법」→SELF)은 **1단계가 확신으로
   잡아 LLM 에 가지 않는다.** 즉 두 층이 서로의 약점을 덮는다. 이 성질은
   우연이므로 **회귀로 고정한다** (§5).

### 3.2 2단계 프롬프트 (검증된 문안)

```
당신은 사내 AI 어시스턴트의 1단계 판정기입니다.
질문 하나를 보고 **사내 자료(매출 데이터·사내 문서·제품 Q&A·개인 메일/일정)를
실제로 뒤져야 답할 수 있는지**만 판정하세요.

NEED = 사내 자료를 뒤져야 답할 수 있다 (수치·기록·사내 규정·내 메일 등)
SELF = 뒤질 필요가 없다. 다음 중 하나다:
       - 만들어 달라는 요청 (초안·구성안·아이디어·번역·코드·문장 다듬기)
       - 이 어시스턴트 자신의 기능·사용법·가능 여부를 묻는 질문
       - 용어의 뜻, 일반 상식, 잡담

주의 1. 질문에 사내 도구 이름(노션·잔디·틱톡샵)이 들어 있다는 이유만으로 NEED 로
        판정하지 마세요. **그 도구에 대해 묻는 것**과 **그 도구의 자료를 찾는 것**은
        다릅니다.
주의 2. 애매하면 NEED 를 고르세요. 뒤져 보고 없다고 말하는 편이, 뒤지지 않고
        지어내는 것보다 낫습니다.

NEED 또는 SELF 한 단어만 출력하세요.
```

- ⛔ **주의 2 를 빼지 마라.** 이것이 「사내 데이터 우선」을 보증하는 유일한 줄이다.
- ⚠️ 판정 실패(타임아웃·에러)는 **NEED 로 떨어진다.** 안전한 쪽 실패다.
- ⚠️ 응답 파싱은 대소문자 무시 부분일치(`"SELF" in out.upper()`)로 한다.
  한 단어만 요구했어도 모델이 문장을 붙일 수 있다.

### 3.3 3단계 — 부정하면 상속을 끊는다

⛔ **여기 처음 적었던 인과는 틀렸다** (2026-09-07 구현 착수 전 실측으로 정정).
「김미이 님이 notion 을 세 번 연속 받은 이유가 경로 상속」이라고 썼는데, 그
발화들은 전부 `_is_followup_utterance()` 가 False 라 **애초에 상속되지 않는다.**
매번 키워드 관문이 새로 판정했고, 그중 둘은 그날 이미 고쳤다(생성 요청 관문 ·
`노션+부재` 확신 제거). 남은 하나는 확신이 없어 **2단계 게이트가 맡는다.**

실측: 실사용 60일 첫머리 부정 15건 중 **상속이 실제로 걸리는 것은 0건**.
그래서 이 절의 「상속 끊기」는 **구현하지 않는다** (YAGNI). 부정 + 후속 발화
형태(`"아니 인도네시아는?"`)가 실제로 나타나면 그때 넣는다 — 네 줄이면 된다.

부정 신호 자체는 **4단계(되묻기)가 계속 쓴다.** 아래 갈래 표도 그대로 쓴다.

실측(1,393건):

| 갈래 | 건수 | 처리 |
|---|---:|---|
| (A) 발화 **첫머리**가 부정 | 20 | **상속을 끊고 다시 분류** |
| (B) 문장 **중간**의 수정어(`말고`·`다시 해`) | 26 | **손대지 않는다** — 정상적인 좁혀 묻기 |

(A) 20건 중 붐따가 눌린 것은 **0건**이다. 스무 건 전부 붐따 없이 지나간
실패이고, 그중엔 환각 신고도 있다 — *"뭔 소리야 틀렸음; 환각을 정답처럼 말하지
마셈"*, *"뭔 소리하는거야. 리센느 멤버 5명을 내부 데이터베이스에서 가져왔다고?"*

즉 이 신호는 붐따와 **겹치지 않는다.** 같은 기간 붐따가 53건이니 실패 가시성이
53 → 73 으로 는다. 붐따를 누르는 사람과 "아니" 라고 쓰는 사람이 다르다.

(B) 를 건드리면 안 되는 이유는 표본이 말한다: "상위 10개 **말고** 전체로 줘",
"막대표 **말고** 원형 그래프로" — 전부 정상적인 좁혀 묻기다.

### 3.4 4단계 — 되묻기는 0.14% 에서만

(A) 중 **부정 말고 아무 정보가 없는 것**만 되묻는다. 실측 **2건 / 1,393건**.

```
"아니..."        "아니 ;;"
```

**「정보가 없다」의 정의** (구현자가 추측하지 않도록 못 박는다): 첫머리의 부정
표현을 걷어낸 뒤, 공백·문장부호·감정 낱자(`ㅠㅜㅋㅎ`)를 모두 지웠을 때 남는
글자가 **4자 이하**면 정보가 없는 것으로 본다. `"아니 ;; 내 개인 업무 노션 ;;"`
은 9자가 남으므로 **되묻지 않고 그 문장으로 다시 라우팅한다.**

- 문구는 **직전에 무엇을 했는지 밝힌 뒤** 묻는다. 그래야 사용자가 무엇을
  고쳐 말해야 할지 안다:
  > 방금은 **사내 문서**에서 찾아 답했습니다. 어떤 걸 원하셨는지 한 줄만 더 주시겠어요?
- ⛔ **LLM 을 부르지 않는다.** 고정 문구다 (보증은 코드다).
- ⛔ SELF 판정 전반에 되묻기를 걸지 않는다. "파이썬 코드 짜줘" 에 되물으면
  그 자체가 불편이다.

### 3.5 SELF 로 답할 때 — 답하고, 밝히고, 한 줄 제안

되묻지 않는 대신, 이미 있는 후속 제안 자리를 쓴다:

```
> 💡 이런 것도 물어보세요
>  · 사내 데이터로 확인해 드릴까요?
```

사용자는 기다리지 않고 답을 받고, 사내 데이터가 필요했다면 한 번 눌러서 간다.

**미결(측정 후 결정, 2026-09-07 사용자 판단 보류)**: SELF 경로가 지금의 큰
direct 프롬프트(회사 소개 + 제품 카탈로그 + 대시보드 카탈로그)를 그대로 쓸지,
가벼운 프롬프트를 따로 둘지. 구현은 **붙일 자리만 만들고 값은 지금 것을 쓴다.**
판단 근거가 될 측정은 §6.

## 4. 어디를 고치나

새 판정은 **순수 함수로 별도 모듈**에 둔다. `orchestrator.py` 는 이미 4,282줄이라
더 키우지 않는다 (`textmatch.py`·`query_keywords.py` 와 같은 방식).

| 파일 | 무엇 |
|---|---|
| `app/core/route_intent.py` (신규) | `SOURCE_GATE_PROMPT` · `parse_gate(raw)` · `rejection_kind(text)` |
| `app/agents/orchestrator.py` | 2단계를 `if not _confident` 블록에 끼운다 (**비스트리밍·스트리밍 두 곳**) · 3·4단계를 상속 판정 앞에 |
| `tests/test_route_source_gate.py` (신규) | 아래 §5 |

⛔ **두 경로에 함께 걸어야 한다.** `route_and_execute` 와 `route_and_stream` 에
각각 `_keyword_classify_ex` 호출이 있다. 한쪽만 고치면 경로에 따라 답이 갈린다 —
이 저장소가 이미 여러 번 겪은 사고다 (direct 프롬프트 두 벌, 수치 검증 미배선).

**걷어내는 것은 없다.** 오늘 감사에서 확신 관문 대부분이 정확했다. 2단계는
확신이 없을 때만 도는 **추가 층**이지 대체가 아니다.

## 5. 테스트

순수 함수라 LLM 없이 대부분 검사된다.

1. **부정 판정** — (A) 20건·(B) 26건 실제 표본을 그대로 고정. `말고` 가 중간에
   있으면 부정이 아니다. 첫머리 부정인데 정보가 있으면 `informative`,
   없으면 `bare`.
2. **상속 끊기** — 부정 발화는 `_inherit_route_for_followup()` 이 None 을 준다.
   부정이 아닌 후속 발화는 종전대로 상속한다 (양방향).
3. **2단계 배선** — 확신이 있으면 LLM 을 **부르지 않는다** (호출 카운터로 확인).
   확신이 없을 때만 부른다.
4. **안전한 쪽 실패** — 2단계가 예외를 던지면 NEED 로 떨어진다.
5. **1·2단계 상호 보호** — 「노션 사용법 알려줘」가 1단계에서 확신 notion 으로
   잡히는지 고정한다. 이게 깨지면 2단계의 위험한 오답이 드러난다.
6. **되묻기 범위** — `bare` 에서만 되묻는다. SELF 판정 전반에는 안 뜬다.
7. **골든셋** — 라우팅만 본다 (판정 임계는 골든셋이 볼 수 없다). 기존 원칙 유지.

## 6. 측정과 되돌리기

**배포 전** — 실사용 1,295건 리플레이로 경로 이동 건수를 센다. 의도한 것 외에
움직이면 원인을 찾고 나서 배포한다 (오늘 세 번 다 이 방식으로 확인했다).

⚠️ **리플레이의 한계**: `_keyword_classify_ex` 는 현재 문장만 받으므로 대화
맥락을 물려받는 후속 발화는 재현되지 않는다. 의심 건은 **프로덕션 답변 원문**으로
확인한다 (2026-09-07 에 이 방법으로 오판 하나를 잡았다).

**배포 후** — 새 로그 세 줄로 본다:
- `source_gate_self` / `source_gate_need` — 2단계 판정 분포
- `route_inherit_broken_by_rejection` — 3단계 발동
- `clarify_asked_bare_rejection` — 4단계 발동 (하루 0~1건이 정상)

**되돌리기**: 2단계를 끄는 설정 하나로 예전 동작이 된다. 3·4단계는 서로 독립이라
각각 끌 수 있다.

**그 다음** — 오늘 만든 감사(경로별 실패 문구 비율)를 `self_check` 에 주 1회로
넣는다. ⛔ 임계는 **비율의 변화**로 건다. 절대값으로 걸면 gws 는 늘 44% 라 매주
울리고, 매주 뜨는 경고는 곧 아무도 안 읽는다.

## 7. 남는 위험

- **부정 감지는 정규식이다.** 새 표현("이게 뭐야", "다시")은 못 잡는다. 목록을
  쌓는 대신 **놓친 것을 세어** 주기적으로 본다. 못 잡아도 지금과 같을 뿐이라
  안전한 쪽으로 실패한다.
- **2단계가 SELF 를 틀리면** 사내 데이터를 안 쓰고 답한다. 프롬프트 주의 2 와
  §3.5 의 한 줄 제안이 완충이지만, 완충일 뿐이다. 배포 후 `source_gate_self` 로
  뽑은 질문을 사람이 한 번 읽는다.
- **일반 질문이 늘면** direct(Opus 5) 트래픽과 비용이 는다. §3.5 의 미결 사항이
  여기에 걸려 있다.

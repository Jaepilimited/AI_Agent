# 라우팅 트리거 지도 — 질문이 어느 데이터로 가는가

> **왜 이 문서가 필요한가**: 트리거가 한 곳에 없다. 결정적 게이트(코드) · 확신 키워드
> 목록 10여 개 · LLM 재판정 · 후속 상속 · BigQuery 안의 테이블 키워드가 **다섯 계층**에
> 흩어져 있고, 계층이 다르면 고치는 방법도 다르다. 실제 오답의 대부분은 "낱말이 없어서"가
> 아니라 **어느 계층에서 잡혔는지 몰라서** 엉뚱한 곳을 고친 것이다.
>
> 작성 2026-08-19 (실측 기준). 코드가 정본이고 이 문서는 지도다 — 어긋나면 코드가 맞다.

---

## 0. 한 장 요약 — 판정은 위에서 아래로, 먼저 걸리면 끝

```
① @@ 지정            → 서버가 강제. 문구를 보지 않는다            (되묻지 않음)
② 결정적 게이트       → FI 차단 → 성분 → 초상권 → 보고서          (코드가 판정)
③ 확신 키워드 분류    → confident=True 면 여기서 끝               (LLM 안 부름)
④ LLM 재판정          → confident=False 일 때만 (Flash)
⑤ 후속 발화 상속      → "그럼 일본은?" 류는 직전 경로를 물려받음
─────────────────────────────────────────────────────────────
bigquery 로 정해진 뒤 → ⑥ 테이블 선택 (키워드 → 스키마 lazy load)
notion 으로 정해진 뒤 → ⑦ 팀 페이지 선택 (벡터 검색)
```

⛔ **③에서 확신을 갖고 틀리면 ④가 구제하지 못한다.** 지금까지 난 조용한 오답은 거의 전부
이 자리였다 (반품→cs, 데이터 분석 파트→bigquery, 사진+"누구야"→direct).

---

## 1. `@@` 지정 — 가장 강한 트리거

- 입력창에 `@@소스명`. 별칭도 같이 잡는다 (`@@bc` = `@@초상권`, `@@리포트` = `@@보고서`).
- **서버가 강제한다.** 프론트가 보낸 값을 믿지 않으며, 지정한 소스는 **되묻지 않는다**.
- 목록은 `orchestrator._DB_REGISTRY` 한 곳 (29개). 프론트는 `/api/datasources` 로 받는다.
- 소스 → 라우트 매핑도 같은 표에서 자동 생성된다 (`_SOURCE_ROUTE_MAP`).

| 그룹 | 소스 | 라우트 |
|---|---|---|
| 보고서 | 보고서 | `report` |
| 매출 데이터 | 매출 · 제품 · 손익 | `bigquery` |
| 마케팅 데이터 | 광고 · 마케팅 · 인플루언서 · Shopify · 플랫폼 · 아마존검색 · 프로모션 · 메타광고 · 국내몰 리뷰 · 해외몰 리뷰 · 매장 리뷰 | `bigquery` |
| BC | 초상권 | `model_rights` |
| Notion | B2B1 · B2B2 · BCM · Craver · CS · DB · GM EAST · GM WEST · JBT · KBT · PEOPLE | `notion` |
| Notion | BP (제품 Q&A) | `cs` |
| 시스템 | Google Workspace | `gws` |

## 2. 결정적 게이트 — 낱말이 아니라 코드가 판정 (순서 고정)

`route_and_stream` / `route_and_execute` 맨 앞에서 이 순서로 검사한다. 걸리면 즉시 처리하고 끝.

| 순서 | 게이트 | 트리거 | 코드 |
|---|---|---|---|
| 1 | **FI(손익) 차단** | 손익 낱말·소스인데 권한 없음 → LLM 호출 **전에** 거절 | `_requests_fi_data()` |
| 2 | **성분 질문** | "나이아신아마이드 들어간 제품" 류 — 제품 목록을 먼저 확정 | `_ingredient_filter_intent()` |
| 3 | **초상권** | ⓐ `초상권` 낱말 ⓑ `모델` + (사진/써도/기한/언제까지…) ⓒ **사진 첨부 + (누구·인물·사람·모델 / 써도·기한·만료·언제까지)** ⓓ **DB 에 실재하는 모델 이름** | `model_rights_intent(q, has_image)` |
| 4 | **보고서** | `@@보고서` 지정 **또는** 질문에 "보고서·리포트·report" | `registry.wants_report()` |

- 3ⓓ 의 이름 목록은 **DB 에서 5분 캐시**로 읽는다 (`_model_names_cached`). 시트에 모델이
  늘어도 코드를 고치지 않는다. 시트 표기가 `김제인 (김정은)` 이면 괄호 안팎을 각각 본다.
- 3 의 짧은 이름(`조`·`소리`·`안나`)은 **단독으로 트리거하지 않는다** — 사진·써도·기한 같은
  보조 신호가 함께 있을 때만. 어절을 조사까지 떼고 비교하므로 `조회`·`안나푸르나`는 안 걸린다.
- 4 는 "분석해줘/정리해줘"로는 만들지 않는다. 반대로 **기능을 묻는 질문**("보고서 기능 언제 써?")은
  `_REPORT_META` 가 걸러 direct 로 보낸다.
- ⚠️ **이미지가 첨부됐는데 3에 안 걸리면 무조건 direct(비전)로 강제된다.** 확신 분기라 ④를 못 탄다
  (`if images: → _handle_direct`). 사진 관련 라우팅을 손볼 때는 반드시 3을 먼저 본다.

## 3. 확신 키워드 분류 — 순서가 곧 우선순위

`_keyword_classify_ex()` → `(route, confident)`. **위에서 먼저 걸리는 것이 이긴다.**

| # | 검사 | 결과 | 가드 (뒤집는 조건) |
|---|---|---|---|
| 1 | `### Task:` 로 시작 | direct ✔ | — (Open WebUI 내부 작업) |
| 2 | 붙여넣은 데이터 있음 | direct ✔ | 조회하면 다른 숫자가 나온다 |
| 3 | 5자 미만 초단문 | direct ✘ | LLM 이 판단 ("B2B" 는 후속 조건일 수 있다) |
| 4 | 인사·잡담·외부 주제 (`_DIRECT_OVERRIDE` 40개) | direct ✔ | 데이터 낱말이 있으면 건너뜀 |
| 5 | 기능 질문 ("차트 그릴 수 있어?") | direct ✔ | HR·팀 낱말이 있으면 건너뜀 |
| 6 | **자기 기능 질문** (`_is_self_feature_question`) | direct ✔ | 외부 플랫폼·툴 이름이 있으면 아님 |
| 7 | **용어 뜻 질문** ("roas가 뭐야?") | direct ✔ | 기간·집계·수량 표현이 있으면 조회 |
| 8 | 전체 데이터 요청 ("다 줘") | bigquery ✔ | — |
| 9 | **팀·HR 낱말** (`_TEAM_KEYWORDS` 97개) | notion ✔ | 데이터 낱말이 함께면 bigquery |
| 10 | **문서 요청어** (가이드라인·절차·"자료 어디") | notion ✔ | 수량·금액어(`_QTY_INTENT`)가 있으면 조회 |
| 11 | 사용법·접속법 (`_HOWTO_KEYWORDS` 30개) | notion ✔ | 넓은 표현은 플랫폼 이름이 있을 때만 |
| 12 | 노션 낱말 (`_NOTION_KEYWORDS` 11개) | notion ✔ | 데이터 낱말이 있으면 넘어감 |
| 13 | **GWS 낱말** (`_GWS_KEYWORDS` 31개) | gws ✔ | **일정류만 걸렸을 때는 범위로 가른다** — 개인(내·메일·드라이브·회의)→gws · 회사 축(프로모션어·국가·몰/채널·팀)→bigquery · **둘 다 아니면 확신하지 않고 LLM 에 넘김** |
| 14 | 데이터 + 검색어인데 **사업 맥락 없음** | direct ✘ | 강등 — LLM 재판정 |
| 15 | 팀 낱말 (데이터 낱말 없음) | notion ✔ | — |
| 16 | **CS 낱말** (`_CS_KEYWORDS` 106개) | cs ✔ | ⓐ 강한 데이터 낱말이 있으면 넘어감 ⓑ **기간+집계**를 함께 물으면 조회 |
| 17 | 데이터 + 외부 맥락 | multi ✔ | "매출 트렌드"는 bigquery |
| 18 | 데이터 낱말 (`_DATA_KEYWORDS` 214개) | bigquery ✔ | **사업 맥락**(`_BIZ_CONTEXT` 138개)이 있어야 확신 |
| 19 | 아무것도 안 걸림 | direct ✘ | LLM 재판정 |

**✔ = confident(끝) / ✘ = LLM 재판정 대상**

### 두 목록을 함께 봐야 하는 이유

`_DATA_KEYWORDS`("데이터 질문인가")와 `_BIZ_CONTEXT`("우리 사업 맥락인가")는 **서로 다른 질문**에
답한다. 한쪽에만 낱말을 넣으면 18번에서 강등돼 엉뚱한 곳으로 간다 — `유가 협업` 이 그래서
사람 이름 "유가연"을 찾아왔다 (2026-08-18).

### 짧은 낱말은 경계를 본다

`app/core/textmatch.py` 한 곳에서 판정한다. `_GUARDED`(9개)에 든 낱말만 앞 글자를 확인한다 —
`라인`이 "가이드라인" 안에서, `환율`이 "전환율" 안에서 걸린 사고 때문이다. **모든 낱말에
경계를 강제하면 안 된다** ("월별매출"의 `매출`은 잡혀야 맞다).

## 4. LLM 재판정 — confident=False 일 때만

- 모델: **Gemini Flash** (속도). 프롬프트에 6경로 정의 + 판단 기준.
- 대화 맥락이 있으면 함께 넣는다.
- ⚠️ 여기서 오분류가 나면 **프롬프트를 고친다**. 키워드를 쌓으면 3번 계층이 비대해진다.

## 5. 후속 발화 상속

| 함수 | 언제 | 무엇을 |
|---|---|---|
| `_should_continue_bigquery_for_correction` | 직전 답변에 **실행 SQL 앵커**가 있고 정정·재조회 표현일 때 | bigquery 유지 |
| `_inherit_route_for_followup` | "그럼 일본은?" 같은 후속 발화 | 직전 경로 상속 |

⛔ **무조건 상속하면 안 된다.** 지표를 가리키는 낱말(유가 협업·ROAS…)은 문서가 아니라
데이터를 묻는 것이므로 상속하지 않고 정상 라우팅한다. 반대로 제품명·국가명·팀명은 축 값이라
그대로 상속한다 ("센텔라 앰플은?" = 그 제품의 매출).

`sql_agent.MARKETING_TABLES` 의 키워드로 **스키마를 lazy load** 한다. 매출/제품은 기본 적재.

|---|---|
| `integrated_ad` (통합 광고) | 광고 · ad · roas · ctr · cpc · cpm · 전환 · 노출 · 클릭 · meta · tiktok · 계정별 · 매체별 |
| `Integrated_marketing_cost` | 마케팅 · marketing · 비용 · roi · 매체 · 팀별 |

| `influencer_input_ALL_TEAMS` | 인플루언서 · kol · 팔로워 · 캠페인 · 시딩 · **유가/무가 협업** · 조회수 · 저장수 · cpv |
| `amazon_search_analytics…` | 아마존 검색 · asin · 장바구니 · 전환율 |
| `Korea_mall_Review` (국내 통합) | 국내몰 리뷰 · 올리브영/무신사/스마트스토어/네이버 리뷰 · 지그재그 · 에이블리 · 29cm |

| `Store_Review` (매장) | 매장/스토어/오프라인 리뷰 · 구글맵 · 네이버 플레이스 · 별점 · **(플래그십\|명동\|뉴욕)+리뷰/후기/평점** |
| `meta data_test` | 메타 광고 · meta ad · 페이스북 광고 라이브러리 · 인스타 광고 |
| `promotion_calendar.promotion` | 프로모션 · 행사 · 기획전 · 캘린더 · 일정 · 스케줄 · 언제 하 · 블랙프라이데이 · 런칭 |
| `FI_LLM_Flat` (손익) | ⚠️ **키워드 lazy-load 가 아니다** — 프롬프트에 상시 포함돼 있고, 권한이 없으면 `_mask_fi_prompt()` 가 섹션을 **잘라낸다** + 화이트리스트에서 제외 + 실행 직전 재검사 |

- ⛔ **통합 리뷰 3종이 정본이다** (2026-08-18). 옛 몰별 소스를 남기면 화이트리스트 밖 테이블을

- ⚠️ **`플래그십`·`명동`·`뉴욕` 은 매출 채널 이름이기도 하다.** 장소 낱말만으로 리뷰 스키마를

  (튜플 = AND, 2026-08-19 사용자 지적).
- ⚠️ `일정·캘린더·스케줄` 은 개인 캘린더(GWS)와 사내 프로모션 캘린더에 동시에 걸린다 →
  **범위로 판정한다** — 3번 계층 13번 참조 (2026-08-19 재설계, 그 전에는 "일본 큐텐 8월 일정" 이 개인 캘린더로 갔다).

## 7. notion 안에서 다시 — 어느 팀 문서를 볼 것인가

- 허용 페이지 목록(`_ALLOWED_PAGES`)에서 **제목 + 벡터 검색**으로 상위 3개를 읽는다.
- `@@팀이름` 으로 지정하면 그 팀만 본다.
- ⛔ 읽어온 문서가 질문과 **한 낱말도 겹치지 않으면 LLM 을 부르지 않는다** (2026-08-19 추가).
  프롬프트에 "추측하지 마라"가 있었는데도 아마존 알렉사·W3C WAI 를 지어냈다 — 지시는 확률,
  보증은 후처리.

## 8. 자주 나는 사고와 대응 원칙

| 사고 유형 | 실제 사례 | 옳은 대응 |
|---|---|---|
| 확신을 갖고 오분류 | "7월 shopify 반품 몇 건" → cs (2.4초 "확인 불가") | 낱말을 옮기지 말고 **질문의 모양**으로 판정 (기간+집계=조회) |
| 낱말이 한쪽 목록에만 | "유가 협업" → direct 강등 → notion | `_DATA_KEYWORDS`·`_BIZ_CONTEXT` **둘 다** 등록 |
| 짧은 낱말 부분 일치 | `라인`이 "가이드라인"에, `인도`가 "요인도"에 | `textmatch` 경계 판정 + `_GUARDED` 등록 |
| 신호를 아예 안 봄 | 사진 첨부인데 초상권 게이트가 텍스트만 봄 | 게이트에 **신호를 추가** (has_image·DB 이름) |
| 목록이 낡음 | 리뷰 통합 후에도 옛 4개만 앎 / 프롬프트의 값 목록 | 데이터에서 **실측**해 채운다 (`value_lists`·`_model_names_cached`) |

💡 **응답이 이상하게 빠르면(1~3초) 경로를 의심하라.** 조회를 안 하고 되묻기·거절로 빠진 신호다.
느린 쪽만 의심하다 놓친 사례가 여러 건이다.

## 9. 새 소스를 붙일 때 등록할 곳

`CLAUDE.md` 의 "새 데이터소스를 붙일 때 건드릴 7곳"을 따른다. 라우팅 관점에서 빠뜨리기 쉬운 것:

1. `_DB_REGISTRY` (@@ 목록·별칭·라우트·그룹)
2. `config.allowed_tables` — 빠지면 **`@@` 로는 되는데 일반 질문만 막힌다**
3. `sql_agent._source_table_map` + `MARKETING_TABLES` (키워드 → 스키마 로드)
4. `_DATA_KEYWORDS` **와** `_BIZ_CONTEXT` 양쪽
5. 값 체계가 다르면 `_localize_*_literals()` 를 **처음부터**
6. 어휘 충돌 확인 — 새 낱말이 기존 확신 키워드와 겹치는지 (`static_checks.keyword_collisions()`)
7. 검증은 **`@@` 지정과 일반 질문 양쪽**으로. 라우팅이 갈리는 지점이 서로 다르다
